4. 向 task11 交接基线版本、下层 actor 哈希、候选与反馈合同、评估清单及可复查基线结果。当前交接仅为计划，尚无训练结果。

### A · 固定下层与输入

主线固定 B3-5M seed4718（冻结清单中最小种子，选择与成绩无关）；4719、4720 仅保留版本记录。两条路径须用同一 final.actor.pt、同一 B3 预处理、确定性动作、eval 模式及动作缩放/裁剪顺序。对同一批原始下层观测逐项比对原版 B3 推理输入及输出，核验 actor、config、几何、地图池哈希，记录 dtype、设备、最大误差与其浮点容差依据。旧权重加载器须先验证格式；禁止形状匹配即放行。

### B · 环境、时钟与奖励

执行采用 B3 配置的同步时序、几何、传感与 primitive-obb 后端。沿用 Core 的 cbl_continue：失败尝试计数并消耗时间，按 Core 的提交掩码更新物理状态，遵守其停止/继续规则。段到点或段超时返回上层；路线末端、累计失败 20、连续停滞 5 及 150 次决策/200 s 尝试时间限额按 Core 优先级结算。严格成功读取复位前 strict_success：路线到末端、TCP 位置残差 ≤0.025 m、旋转残差 ≤0.05 rad，且累计失败为零。分别记录到达、有失败的完成、失败上限、停滞和限额。

推演克隆决策边界的状态、路线、已观测地图与时间戳、队列、上一动作、累计失败和剩余限额。每槽用相同 B3 在局部地图副本上推演一段；无未来扫描、无全图碰撞真值。采用相同尝试/提交、失败上限与段停止规则。失败后继续时另存首次失败及累计失败作审计；19 维槽中首次失败时间比例用首次失败尝试时刻/段时限，无失败为 1，末因按实际结束原因，段耗时用尝试时间。风险仅来自局部观测。整批推演不得修改真实状态、计数器、传感器或 RNG。用完全已知且碰撞表达一致的确定性夹具比对推演与执行，另用部分观测夹具验证真实执行可因新障碍与推演分歧。

上层以完整回合为有限时域。每段时长 dt = 尝试子步数 × 0.05 s，同时记录提交时间。折扣 g = 0.99^(dt/0.1 s)，继承旧上层时间尺度，改用 B3 尝试时钟。基础奖励仅在严格成功首次结束时为 1，其余为 0。为给中间选择提供信号，设 Phi = 已完成路线弧长/总弧长（米/米，限定有效非零路线）；下一状态为任务终局时 Phi_next=0。训练奖励 r = strict_success_event + g × Phi_next − Phi。按同一折扣累乘，塑形项在整回合求和为 −Phi_initial；失败终止前的累计进度不会成为最终奖励。记录原始奖励、塑形项和折扣；熵和时间折扣会影响训练偏好，最终验收直接数严格成功。任务内决策/时间限额均结束本回合，上层不 bootstrap；保留原 terminated/truncated 与独立 bootstrap_mask。进程中断或采集切块不伪造任务结束。

### C · 学习器与验证顺序

1. 复用 task7_upper 的同步 VCM → 候选编码器（状态 token 与有效候选注意力）→ stage 1 actor/双 Q。沿用该阶段的梯度隔离，只更新上层可训练参数；逐模块记录梯度及下层前后哈希。禁止加载预测分支参与评分。
2. 每次真实选择写一条回放，含当前/下一候选批、观测、k、r、dt、结束与 episode ID。计算 y=r+bootstrap_mask × g × Σπ_next(min Q_target−α log π_next)。两个 critic 只拟合该条的 Q(s,k)；actor 按有效槽概率对 α log π−min Q 求期望。目标网络软更新。用手算夹具测试仅一个有效槽、失败零提交但 dt>0、严格成功与两类限额。短回合和首段也必须能贡献 critic 损失：从同回合历史恢复记忆；不足 burn-in 的回合从初态开始，仅对真实位置求损失。断言跨回合拼接、padding、未选候选的伪标签均不进入损失。
3. 初始训练设置沿用 upper_train.json 的上层字段：随机有效选点预热 1000 次真实决策，容量 100000，32 段序列、长度 8、最多 4 步 burn-in；预热后每新增一条真实决策安排一次更新，记录实际更新/决策比。沿用离散 SAC 的温度规则、target_tau 0.001、梯度裁剪 10、学习率 1e−4 到 1e−6，按本次运行预定更新数调度。试训与正式运行独立初始化。预算计量只计真实上层决策，另列推演槽数、B3 调用及子步。
4. 派发后的首次有界核查：先 CPU/小批确定性接口夹具，再用 train split 做单一上层种子 101、至多 1200 条真实决策、至多 200 次更新的冒烟；墙钟上限 30 分钟（自启动冒烟计），先到即停。用未参加训练的 validation 地图取按 ID 排序的前 4 张，各用固定场景种子 101，各跑一次 actor 和均匀随机参照，随机策略独立 RNG 固定 102；配对读数仅查管线，评估另限 30 分钟，超时保留缺失记录。若资源或场景不足、未验证有效梯度或未完成配对，记录不完整。禁止自动扩预算。非有限、泄漏、B3 不一致、失败被丢弃、恢复后重复计数立即停止。恢复验证比较同一检查点接续的 RNG、下一采样与更新计数；不支持环境中途恢复则明确仅在可重建边界保存，并验证无漏计。
5. 分开实测复位、候选/推演、执行、回放搬运、update、日志与 checkpoint 的吞吐和耗时分布；记录真实设备、峰值显存、墙钟、并行与线程设置。按端到端测量估算正式各部分成本。依赖的主仓产物使用绝对路径只读，工作树内新产物进入 task10 专属 logs/results。

### D · 正式运行与交付条件

正式运行前锁定训练种子、交互预算、时限、评估清单、配置/代码/actor 哈希；依据 C 的成本交决策者、用户核定。按 map_id 分离 train、validation、test；复用基线地图清单，先查三集合互斥及生成后的场景身份。正式 actor 取预定预算最后一次 checkpoint，不按 test 选模。配对单位为地图、场景种子、初始状态、路线和冻结下层；记录初态哈希。参照与 actor 同一环境和预算口径。为 task11 保留该清单及种子，共享相同可见信息、候选、执行规则和预算口径。

主指标 = 严格成功数 / 预登记完整回合数。按策略和训练种子分别列预期数、完成数、严格成功数、各结束原因、分地图结果及成对胜/负/平。缺失单列；有缺失时只报成功率上下界 [成功数/N, (成功数+缺失数)/N]，完成性验收不通过。报告段到达率及其分母、每回合失败数/尝试时长作为诊断。基线交付要求清单完整、可复核、无泄漏且可恢复；相对参照的收益按观测如实报告，有界试训无性能门槛。正式交付须附 checkpoint、逐回合明细、配对复算命令和资源证据。

推荐 GPT6.1sol/high 或 Sonnet5.5/high。重点复核失败时钟、回放边界与任务内限额的 Bellman 掩码。

### 子 Agent 派发与验收

执行负责人获授权自行拆分、派发子 Agent，并选择平台可用的合适模型和推理强度。[授权记录](../../SOURCES.md#src-t10-002)。按根 AGENTS.md，派发前建立稳定编号的子任务三文档及独立日志，更新父流程链接、依赖、负责人、模型/强度、输入、独占写入范围、交付与验收条件。

默认选 GPT6.1sol 或 Sonnet5.5。清单与哈希核对用 low，按定稿接口实现与测试用 medium，跨层失败时钟、终局折扣、回放边界和集成审查用 high；确需换模型时记录理由、可用型号和实际配置。可先并行开展 B3 输入/动作核验与 SAC 回报/回放夹具，两者分开写文件；依赖接口的集成按 A→B→C 推进。父 Agent 负责共享文档和唯一的试训账本，复查差异、复跑关键夹具、统一启动有界试训并签收。所有子 Agent 共用父任务预算。
