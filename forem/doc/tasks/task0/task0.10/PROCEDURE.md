# task0.10 task0.9复核问题修正 — 流程

遵循根AGENTS递归规则：一任务一目录，TASK/PROCEDURE/RESULTS 三文档；本节点不再拆分子节点，由 Claude 顺序执行，不委派。

## 顺序与依赖

1. **接手**：读 task0.9 三文档、复核代码审核日志与 `results/task0/task0.9-checks/*` 复现物；登记进度与独立日志；确认 forem-dev 内无外来进程。
2. **进程所有权（P1+P2-orphan）**：用 Linux child-subreaper 监督进程持续记录本次进程树身份；stop 仅对“身份仍匹配的已确认成员及其后代”发信号，不再从失效 root 的裸 PID 扩展；父先退出、监督进程被杀、已有 cleanup 记录仍残留等路径都要清理并如实报告。先写真实进程回归（会在旧逻辑下失败的场景），再改实现。
3. **高频分析（P2）**：分析入口做 schema/有限值/时间顺序/非空检查，顶层证据不足一律非零，每关节连续步三元组 ≥100 与窗口内覆盖比例，非有限评价值失败；先写坏输入回归。
4. **窗口（P2）**：wrapper 从 `summary.json` 读请求窗口与运动时刻/时长，分别评价请求窗口、运动段、停稳段，报告各段样本/覆盖；先复现“短时交替被整 bag 稀释”的合成数据，再证明新逻辑判失败。
5. **重验**：单元/回归、构建、新 run-id 的 fresh 两次启动、60 s 保持、高频保持/运动、阴性对照；旧数据按窗口重算。
6. **文档**：RESULTS 闭环表、父 task0 RESULTS、task0.7 RESULTS 追加、ENV、PROGRESS、DECISIONS（如有）、独立日志。

## 规则

- 不用宽泛 pkill；测试只对自己创建的进程发信号；外来进程场景用身份不匹配的自建进程模拟。
- 保留历史 run 与旧证据，新 run-id 不复用；已有判据阈值不为通过而放宽（如需改先记录理由）。
- 未执行的写“尚未执行”，通过结论只来自实际运行。
