## 1. 数据与种子

- 训练种子首轮为 11、22、33；烟测/筛选可仅用 11，但不能据此宣称跨种子稳定。
- 训练布局/episode seed 使用 0-9999，验证 10000-10099，最终测试 20000-20299。P0 的快速确定性复测使用验证区间中的前 20 个，正式测试在选型后运行。
- 每个 episode 单独设定环境随机数；策略、数据采样、扰动、熵估计使用独立 RNG。seed 不保证场景独立，还须保存布局摘要并检查重复布局。
- 世界模型按完整 episode 分割；新布局泛化要留出布局或场景类型，不能仅换动作随机数。
- 任务参数、难度、地图尺度和指令条件固定；不得根据最终测试表现调整训练或阈值。

## 2. 每次运行的 manifest

必须包含：run_id、时间、Agent/任务 ID、根与所有被修改子仓库 HEAD、dirty diff 哈希、容器/镜像 ID、依赖及实际模块导入路径、完整配置、checkpoint SHA-256、数据/seed manifest 哈希、观测/动作/终止语义版本、训练步数和更新次数。

推荐拟建产物布局为 `results/<run_id>/manifest.json`、`episodes.jsonl`、`summary.json`、`timing.jsonl`、`logs/` 和必要轨迹分片；建立目录时同步 Git ignore。doc 仅存表格摘要和这些产物的路径/哈希。

每回合记录：task/world/seed、初始观测 SHA-256、success/perfect-success、碰撞计数、IK 计数、主/次终止原因、terminated/truncated、回报、轨迹长度、步骤、仿真时长、wall time、异常及 checkpoint 版本。

初始观测哈希使用固定字段顺序、shape、dtype 和字节序，不通过字符串 repr 生成。Gazebo 同时记录启动位姿、场景配置、时钟/传感器状态；图像与浮点时序无法逐字节一致时，不能冒称 analytical 级确定性。

## 3. 任务与指标

| 用途 | 任务 | 必报结果 |
|---|---|---|
| 快速迭代 | simpleobstacle | SR、perfect-success、碰撞、IK、终止类型 |
| 主任务 | picknplace | 同上，增加子任务完成率、轨迹和耗时 |
| 记忆专项 | dynobstacle + 固定观测扰动 | 各强度 clean/受扰动结果、图龄、延迟 |
| 泛化 | bookstorepnp / 留出布局 | 同上，明确训练中未出现哪些因素 |

perfect-success 必须是任务成功且按既定计数无碰撞/IK 失败。不同计数语义不得混合。轨迹长度取实际基座位置相邻距离之和，失败轨迹同样纳入；控制耗时报告 p50/p95/p99 和超时率。

## 4. 训练预算与选型

- 工程烟测：先 2000 环境步，验证更新/保存/恢复，不作收敛结论。
- 初筛：每变体 100000 环境步、训练 seed=11；每 20000 步在固定验证集评估。初筛只淘汰错误或明显无效方案。
- 首轮正式预算：每变体 500000 环境步、3 个训练种子，每 50000 步验证；以预算末端 checkpoint 为主结果，不挑测试最优 checkpoint。每 20000 步及正常退出保存可恢复 checkpoint。
- 正式预算可依据初筛曲线统一调整，但必须在正式测试前记录，对所有被比较变体一致。500000 步是成本预算，不代表必然收敛；明显未收敛时如实报告或统一延长。
- 同时匹配/报告 actor、critic、world model 更新次数、离线数据量和额外预训练算力。只匹配环境步数不足以说明算力相同。
- 启动长训练前按实测吞吐估算每变体 GPU 小时和磁盘峰值，写入任务日志；不自动启动所有组合形成无人管理的长队列。

## 5. 对照层次

基线层：历史 checkpoint 原语义（仅溯源）、修复后 SAC、修复后 prior-SAC。P2 首轮主线使用修复后 SAC；prior-SAC 作为扩展条件，不能在不同变体间随意更换。

最小闭环层：相同固定编码器/actor head 训练条件的无修正对照、相同输入与近似容量但不接前瞻的适配器对照、真实前瞻修正。delta=0/打乱为训练后诊断，不能替代分别训练的结构对照。

时序层：同 GRU/latent 与训练窗口、关闭修正的对照，以及开启修正版本。P3 额外匹配记忆以外的容量/训练预算；P4 冻结/周期/条件适应保持相同初始 checkpoint 和 P3 开关。

“只加世界模型辅助损失”仅在编码器或策略确实共享并接受该损失梯度时成立；若世界模型完全独立且冻结，不能把它包装成已改变策略训练的辅助损失对照。

## 6. 统计与阶段判据

- 逐训练种子报告所有指标，再报告种子均值和变异；用同 episode seeds 配对比较。可按训练种子与 episode 分层 bootstrap 估计 95% 区间，注明训练种子仅 3 个时区间不稳定的限制。
- 主指标默认 goal-reached SR。声称“提升”要求预先指定的主比较 SR 差值 95% 区间下界大于 0；其余对照标为探索性，不能从多组结果中挑最有利者充当预注册主结论。
- 不预设“统计不显著即不掉点”。若研究非劣效，必须先根据任务需求写出 SR/碰撞容许边界再测试；本版不声称已定义非劣效标准。
- perfect-success、碰撞和 IK 同时报告；若 SR 提升而碰撞/IK 变差，标为权衡，不能称“全面改善”。进入下一研究阶段允许探索，但 P2 成果不能仅靠 SR 掩盖风险退化。
- 预测误差按 episode 汇总后比较，分别报告状态块与地图块；1/5 步开放循环不使用真实中间特征。
- analytical 确定性复测要求固定 checkpoint、初始化和种子，两次逐回合检查；若不一致先调查。Gazebo 使用同启动条件和随机种子做统计复测，不要求整条传感器流哈希一致。

## 7. 异常、适应与数据泄漏

- 崩溃、缺帧、无法 reset 的 episode 单列；汇总必须报告计划数、有效数、异常数，禁止静默丢弃。方法引发失败计入任务失败，基础设施故障按记录规则重跑并保留原记录。
- P4 的模型/optimizer/记忆/阈值历史默认每回合重置；其在线学习只消费该回合截至当前已观测数据。测试顺序与跨回合累积学习是不同协议。
- 模型/阈值/超参数选择只用训练和验证集，所有变体固定后再进入最终测试。测试发现错误后修复需说明并重跑受影响对照。
