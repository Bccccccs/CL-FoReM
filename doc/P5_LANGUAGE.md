# P5 - 可选 RGB-D 与语言条件化详细安排

> **模块参考（DOCS-028）**：主线之外，需用户另行决定；见 [ROADMAP](ROADMAP.md)。

> 当前状态：不启动。仅在 P2 收益已验证且用户明确决定开展后，按 AGENTS.md 登记任务并使用 executing-plans 技能实施。

**目标**：将已验证的移动操作闭环方法扩展到指令条件任务，并区分传感器增加、语言输入与闭环修正各自贡献。

**架构**：RGB-D 与机器人/地图观测通过显式版本的新观测接口进入编码器；冻结文本编码器提供指令向量，条件化 posterior/策略特征。旧 P1-P4 接口继续可用。

**技术栈**：ROS 图像话题、D435 xacro、现有 PyTorch 与经兼容性验证的冻结图像/文本编码器。

**依据**：[总体边界](../AGENTS.md)、[P2](P2_CORRECTION.md)、[评测](EVALUATION.md)。

## 范围与接口

可能修改根仓库 `src/husky_ur5/urdf/husky_ur5.xacro`；主包拟新增 `wm/rgbd.py`、`wm/language.py`、独立任务指令 wrapper 和对应 tests。跨独立仓库的改动分别记录 commit/diff。

新观测字段包括 rgb、depth、各自 timestamp、相机内参、有效性 mask、instruction_id 与文本向量；旧 robot_state/map 字段不重排。观测版本、模型 checkpoint 和预处理哈希写入 manifest。

## 任务步骤

- [ ] 先决定本阶段问题是“语言条件移动操作”还是完整 VLN 基准迁移；本计划默认前者，不因为接入一句指令就宣称复现 VLN benchmark。
- [ ] 恢复 D435 并核实图像、深度、内参、TF 和时间戳；Velodyne 频率独立配置，性能影响独立测量，不与算法收益同时变化。
- [ ] 验证 RGB-D 队列、同步误差、缺帧处理、depth 单位/无效像素和观察延迟；只使用决策时已到达的图像。
- [ ] 在显存/延迟 profiling 后选择可在现有 Python/PyTorch 环境运行的冻结编码器；如需现代依赖，先设计进程隔离并单独固化环境，不能直接升级主 RL 依赖破坏基线。
- [ ] 定义任务模板、目标物体、动作顺序与可执行约束；同一场景设计不同合法指令，确保语言会改变任务而非只是复述固定目标。
- [ ] 数据按布局、目标组合和指令模板分别划分；测试包含未见措辞与组合，禁止训练模板 ID 直接泄漏测试目标。
- [ ] 保持原几何目标条件对照，比较“新增 RGB-D 无语言”“RGB-D+语言无修正”“RGB-D+语言有修正”；训练预算与视觉编码器一致。
- [ ] 做移除/打乱指令诊断，确认策略使用语言；若显式几何目标已完全决定动作，分析语言是否冗余并如实报告。
- [ ] 验证旧观测版本仍能运行 P1-P4，缺失新字段时明确回退到已定义模式或报错，不悄悄填零。

## 验收

- 工程：传感器校准/时间同步、有效性 mask、观测版本兼容、缺帧和指令解析回归通过。
- 任务：同场景不同指令产生符合各自目标的行为；组合/模板留出集有独立评估。
- 研究：闭环增益必须在同 RGB-D/语言条件下比较；语言收益必须有无语言或指令打乱的证据；报告 SR、步骤完成率、碰撞、IK 与延迟。
- 若准备对齐 VLN，另建立与对应 benchmark 一致的任务、输入和指标协议；模板移动操作数据不能直接与 R2R/RxR 表格比较。

## 合理性与风险

P5 会同时扩大感知、任务和依赖范围，因此作为独立扩展，不能成为早期 P0 的强制开工项。语言条件化在概念上不必须依赖 RGB-D，但本阶段若研究视觉语言任务，必须有真实视觉输入及其贡献验证。

交付传感器/观测版本说明、任务与指令数据规范、编码器与延迟报告、语言/视觉/修正三者分离的对照。重点审查目标泄漏、语言冗余、异步观测、旧模型失配和研究任务命名过度。
