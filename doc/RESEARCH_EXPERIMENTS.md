## 1. 研究问题与当前可成立的结论

研究问题：在相同 Husky 任务、SAC 最终动作职责、数据和训练预算下，世界模型每步前瞻产生的执行前特征修正，能否利用持续到来的真实反馈，比无修正、仅增加适配器、只在初始时刻修正的对照取得可重复的任务收益？

当前观测是 41 维机器人状态和 120×120×1 局部地图；P1 固定特征为 41+1000=1041 维，动作3维。当前 SAC 本来就在每步使用新观测，是已有反馈策略；不能把“加入反馈”本身当作全部新贡献。待检验的增量机制是 **真实观测 → WM 前瞻 → 特征修正 → SAC 动作 → 执行 → 新真实观测** 的循环。P1 给定记录动作序列的1/5步预测不等于该闭环，世界模型也不直接选最终动作。

继续沿用数据的规则：

1. 已有训练分片、旧测试结果全部保留，不覆盖或删除。对扩充模型，旧test只作“已曝光/后来纳入训练的诊断集”，不得报告其留出泛化。
2. 将已有manifest组合为统一曝光登记：dataset_id、episode身份、layout/goal/initial_obs哈希、policy/encoder版本、种子/RNG来源、首次用途与查看日期。仅改目录、重采同种子或重新划分文件不能恢复测试独立性。
3. 下一轮首先只在train/val上做资源检查和诊断。dataset-v2-10k的val可用于选型；它不因此成为最终测试。冻结模型、超参数、统计比较后才启用全新未曝光集合。
4. 不在本文随意另选“新种子”。旧0–9599已入扩充train，9600–9899已作val，9900为占位；原EVALUATION还保留10000–10099验证及20000–20299闭环最终测试。新P1最终测试需先审计全部历史使用记录，再以协议修订登记独立命名空间/范围及布局隔离。
5. 当前 [collect_rollouts.py](../src/modulation_rl/scripts/collect_rollouts.py) 与 `p0_runner.read_seeds` 将采数限制在0–9999；若新隔离集超出此范围，须先版本化修改采集准入规则，保留原评测保护。本文不提供一个当前代码无法执行的“新测试”命令。
6. 同一完整episode只能属于一个当前实验split；连续窗口不跨episode，子目标切换是否排除需预先冻结。train统计量不能读取val/test；held-out scene需按布局/场景族划分，不以换随机动作替代场景泛化。

manifest路径与全SHA-256、可复查交集代码、实际抽样文件哈希见[本次审计记录](agent_logs/20260928-research-experiments.md)。本轮未新增数据、重跑模型、修复划分或宣称全量数据完整性验收。

## 5. 最小消融与分阶段扩展

不一次铺开所有组合。每增加一个机制，先登记其可证伪假设与对应对照；未引入的模块不安排虚构消融。

| 消融 | 阶段 | 机制假设 / 否定信号 |
|---|---|---|
| action vs no_action vs copy | P1a，已有 | 动作提供可用动态信息；一步不能同时稳定优于两对照则不满足出口 |
| 数据量学习曲线 | P1a下一轮候选 | 训练量是瓶颈；同一未变val、嵌套train子集、同encoder/配置，统一更新预算视角；扩大后仍无copy优势就不能继续只归因数据少 |
| 动作/目标时间对齐、Δ目标标准化 | P1a诊断候选 | 有效动态被尺度/对齐掩盖；只能train/val选型。现MLP已做残差输出，真正新变体应是Δ本身统计量/监督定义，不能把“改成残差”当未有实现 |
| B1/B2/C1 | P2首要 | 前瞻信息有增量价值；C1仅优于较弱B0却不优于匹配结构B2时不支持主claim |
| 初始一次 vs 每步修正 | P2 | 反复融合预测和新反馈有效；两者无可靠差异时不支持闭环增量claim |
| WM预测差置零/打乱、记录修正范数 | P2训练后诊断 | 是否使用预测信号；不是公平训练对照，打乱输入会有分布外风险，应标诊断 |
| 1步 vs 更长horizon、修正频率 | P1/P2 | 更长前瞻/更高频率有益；先过多步预测检查，统一计算预算。旧5步报告受D33影响；正确重测前不默认增大horizon |
| robot-only/map-only/full | P1/P2按失败分析需要 | 哪类观测提供修正信号；保留任务目标条件，标明容量与信息变化 |
| GRU/记忆/扰动开关 | P1b→P3 | 记忆对受扰观测有效；同历史长度、容量、数据及burn-in，不能与无历史弱对照混比 |
| 冻结/周期/条件更新 | P4 | 条件更新有更好效果/成本；逐episode重置且不看未来，仅可访问截至当前真实反馈 |

## 6. 鲁棒性、泛化与资源实验

全部是待登记并执行的设计，未声称当前支持全部扰动注入。

| 范围 | 首选测试与对照 | 入口/限制 |
|---|---|---|
| 同任务留出分布 | 未曝光初始状态/目标/布局；所有变体同episode配对 | seed互异不足以替代布局审计；先修跨版本隔离 |

| 动态障碍 | 固定运动脚本/随机源与难度；clean/动态配对 | dynobstacle尚未实测，不将任务名存在当验收通过 |
| 控制扰动/模型误差 | 在执行端注入有物理定义的延迟/控制误差，记录实际执行动作及dt | 不把改观测冒称动力学失配；改变P0环境语义需单列版本并重跑所有对照 |

| 载荷/机器人配置/真实硬件 | 后续条件允许再登记 | 当前无已验收接口或实机证据，列limitation，不作为本轮完成条件 |

正确性先决条件：先修D33时间偏移并用已知序列逐项验证非零t、首尾窗口、不同episode长度、1/5步动作与dt对齐；训练、val_probe和评测必须共用受测试覆盖的取窗实现。改变取窗会改变训练分布与评测目标，旧checkpoint不能直接恢复训练冒称可比，需新run_id重训相关对照。

资源先决条件：修复 `EpisodeDataset` 的全量地图加载只是第一步；现 `window_tensors` 还将全部窗口放device，epoch末还做整train/val前向。应沿现有入口将编码、缓存、采样、验证、预测评测分块化，避免把主存OOM移到GPU。历史D29的236GB RSS/51GB swap为9月24记录，本轮没有重现；当前空输出目录不能证明新训练成功。

资源验收先取小样本核对新旧输入/特征/损失一致，再逐级增加数据并记录峰值RSS、swap、GPU进程显存、IO、吞吐；在独立新输出目录预检通过后才安排长任务。预算阈值根据当前空闲资源和共用ROS进程预先冻结，不以“机器有大显存”替代测量。GPU `max_memory_allocated` 不包括全部进程/驱动/主存。

硬件报告沿用[ENV](../ENV.md)并在每次实验manifest核实。历史node01是Ubuntu22.04.5、4×RTX PRO6000 Blackwell、容器Python3.10.18/Torch2.7.1+cu128/Noetic；旧2080Ti/11GB约束是来源机器历史。实际分配GPU、CPU/RAM、驱动、CUDA、容器镜像ID、源码导入路径、并发负载需本次运行采集，本文不冒称重新完成环境验收。Gazebo20ms与analytical0.1s分别定义超时，不能用一种配置替另一种证明实时。

## 7. 统计、失败记录与claim对应证据

沿用EVALUATION主指标goal-reached SR、同episode配对、逐训练seed结果、均值/标准差及分层bootstrap95%区间。P1以episode而非高度重叠窗口为统计单元；核心控制结论至少区分策略训练seed与episode seed，不能用300回合掩盖只有1个训练seed。3训练seed的不确定性仍很大，应如实报告。

正式结果前登记：研究问题/主比较/主指标、最小有意义改善、训练与测试预算、异常规则、停止/选型规则、扰动强度、checkpoint来源、数据曝光登记和统计脚本版本。优效主claim按现协议要求配对SR差CI下界>0；“不显著”不等于非劣效。安全非劣效边界尚未定义，不能先承诺“安全性不下降”。碰撞/IK变差则报告权衡。

除预先指定主比较外，其他消融标探索性；多个共同主比较需事先设层级或多重比较校正。不得在看到测试后换主指标、换种子或只挑有效场景。模型导致异常计入失败；基础设施异常保留原记录，以新run_id重跑受影响对照。汇总同时给原始/有效/异常数量，缺失碰撞标签不能填为“零碰撞”。

| 候选claim | 至少需要的证据 | 当前状态 / 否定后的行动 |
|---|---|---|
| C-PRED：动作条件动态可稳定预测 | 正确取窗、同encoder下1步action相对copy和no_action均稳定改善；多步如实报告 | 修复后单seed val初步成立（D36）；跨seed与独立test待ROADMAP R0-1/R0-2 |
