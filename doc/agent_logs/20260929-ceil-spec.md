# CEIL-028 设计说明：SAC 上限摸底（能不能涨）

- 编写：Claude Opus 5.5 /ybc（协调方，仅写文档），2026-09-29。
- 实现与启动：交给执行 Agent（见 [启动提示词](20260929-ceil-prompt.md)）。
- 判据预登记：D57，写于实现之前，**实现与运行中不得修改**。
- 形式：执行 Agent 写代码、验证、一次性启动无人值守流水线后结束；流水线跑完自动生成报告。

## 1. 要回答的问题

到目前为止，在 simpleobstacle 上无论怎样干扰或帮助 SAC，成功率都停在 0.70 左右（执行失配、观测延迟、世界模型补偿、前瞻、在线适应）。在决定下一步之前，需要先确定：

1. **0.70 是 SAC 没学够，还是任务的天花板？** 训练得更久，成功率能不能明显上涨？
2. **SAC 的决策到底有多重要？** 不动脑子的简单策略能做到多少？

两个答案组合起来，直接决定研究从哪里下手（§5）。

## 2. 关键事实（设计依据）

- 现有基线 policy-100k：seed 11，训练预算 10 万步，评测种子 10000–10099 上成功率 0.70（R0-3c 名义配置，确定性，fixed100）。训练配置见 `results/p1a-20260923/sac-screen-100k/manifest.json`：batch 256、random_steps 1000、replay_capacity 100000、save_interval 20000、ik fixed 100、max_episode_steps 2000。
- **学习率按整个训练预算指数衰减**（`sac.py:45`，从 `lr_start` 衰减到 `lr_end`，衰减长度为总步数）。policy-100k 在 10 万步时已衰减到底。因此：
  - **不要**从 policy-100k 续训到 30 万步：后 20 万步会一直停在最低学习率，不是公平的“训练更久”；而且续训协议记录了 `total_steps`，直接改预算会被 `load_training` 以 “Resume configuration mismatch” 拒绝。
  - 改为**从零训练、预算 30 万步**的新策略。它们在 10 万步时的检查点与 policy-100k 并不等价（学习率曲线不同），只作为学习曲线上的一个点。
- 执行 Agent 需先核实 `num_steps` 确实取自 `--steps`；若不是，停下来说明。

## 3. 实验内容

### E1：训练更久（主实验）

- 从零训练 SAC，**预算 300000 步**，训练种子 **11 和 22**，其余配置与 policy-100k 完全相同。
- 可以使用 D55 的 `--replay-compact-maps`（地图以布尔值存储，采样数值与原来逐位相同），以控制内存和检查点体积；需在 manifest 中记录。
- 每 50000 步保存检查点：50k、100k、150k、200k、250k、300k。
- 每个检查点在种子 10000–10099 上评测 100 回合（确定性、`--ik-mode fixed --ik-iterations 100`）。检查点一出现即可评测，不必等训练结束。
- **主结论只看 300k 预算末端的检查点**，不挑中间最好的。

### E2：简单策略对照（不训练，约 15 分钟）

`p0_runner.py` 评测新增默认关闭的开关 `--policy-override {random,mean,slow-ee}`：

| 策略 | 做法 | 目的 |
|---|---|---|
| random | 每步动作在 [−1, 1] 内均匀随机，随机数由回合种子派生 | 最低水平 |
| mean | 每步输出固定动作：policy-100k 在 R0-3c 名义 100 个回合中所有动作的逐维平均值（由数据计算，不手调） | “不看状态”的策略能做到多少 |
| slow-ee | policy-100k 正常出动作，但第 0 维（夹爪沿路线速度）固定为 −1（最慢） | 探索性：给底盘更多时间跟上，本身能否提高成功率 |

每个策略在种子 10000–10099 上评测 100 回合。开关关闭时不导入新代码、不产生新字段。

## 4. 判据（D57）

- **C-learn（学习空间）**：两个 300k 末端检查点的成功率，相对 policy-100k（0.70，同评测种子）提升 ≥ 0.10，且“训练种子 × 回合”分层 bootstrap 的 95% CI 下界 > 0。
- **C-policy（策略重要性）**：SR(policy-100k) − max(SR(random), SR(mean)) ≥ 0.30。
- slow-ee 与学习曲线中间点只作报告，不作判据。
- 另报：perfect-success、IK 失败回合比例、碰撞回合比例、平均步数、两个训练种子各自的学习曲线、训练耗时。

## 5. 结果对应的下一步（预登记）

| C-learn | C-policy | 含义 | 下一步 |
|---|---|---|---|
| 通过 | 通过 | SAC 的决策重要，且还有学习空间 | 做“世界模型帮 SAC 学习”：先做辅助预测任务（重点预测 IK 可行性），比较相同训练步数下的学习曲线 |
| 不通过 | 通过 | SAC 已接近该任务的天花板 | 换任务（door / drawer 等），先做同样的上限摸底 |
| 不通过 | 不通过 | 任务对策略不敏感 | 换任务 |
| 通过 | 不通过 | 结果矛盾，需检查实验 | 停下来核查后再决定 |

最终方向由用户确认；报告只陈述结果。

## 6. 流水线与启动前验证

- 分支：从 `screen-028` 新建 `ceil-028`。
- 入口：宿主启动脚本 `doc/agent_logs/20260929-ceil-launch.sh` → 容器 `mmhusky-node01` 内 `nohup` 运行 `src/modulation_rl/scripts/ceil_pipeline.py`；输出根目录 `results/ceil-028/`；状态文件 `results/ceil-028/status.json`；自动报告 `doc/agent_logs/20260929-ceil-report.md`。可以复用 `screen_pipeline.py` 的编排、资源守护、续跑与统计代码。
- 阶段：S0 预检 → S1 E2 简单策略（与训练并行）→ S2 两个训练进程 → S3 检查点逐个评测 → S4 汇总报告（先写点估计，再算 CI）。
- 超时：每个训练 20 h（30 万步约 10–13 h）；训练中断时从最近检查点续训（续训不改预算，协议一致）；每次评测 1 h。
- 资源：episode-worker 总数 ≤ 64；启动新批次前可用内存 ≥ 60 GiB。
- 新代码放在 `scripts/` 顶层，不放进、不修改 `scripts/wm/`。
- **启动前必须完成**（写进任务日志）：
  1. 默认关闭回归：种子 10000–10019 不带新开关评测，与改动前逐字段一致；
  2. 单元测试：三种 override 的动作生成（random 可复现、mean 的计算、slow-ee 只改第 0 维）；现有测试全部通过；
  3. 冒烟：训练 2000 步、每个评测臂 4 回合，全流程跑通并生成报告（`results/ceil-028-smoke/`）；
  4. 按路径提交到 `ceil-028` 后再启动；确认两个训练进程和 E2 评测已运行后，写好监控、停止与续跑方式，结束会话。
