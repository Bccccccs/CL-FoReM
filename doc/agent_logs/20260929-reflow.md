## 代码事实核对（“全局”具体在哪里）

1. **规划器用全图**：simpleobstacle 用 `PointToPointPlanner`（`tasks.py:368`）。回合开始时 `_reset` 由整张地图生成 A* 代价 `self._weights`（`eeplanner.py:579` → `generate_base_feasible_eeweights`/`map_to_weights`），此后每步 `generate_obs_step` 在这份**全图代价**上重跑 A*（`eeplanner.py:617,651`）；只有地图变化（动态障碍）才重算代价（`combined_env.py:392-394`）。
2. **高度插值也读全图**：`_calc_6Dplan` 用 `self._map._floorplan_img_filled` 读路径上障碍高度（`eeplanner.py:629`，另 448–456）。
3. **SAC 输入**：41 维状态里含下一末端参考位姿与目标（`combined_env.py:_to_agent_obs`），参考来自上述全图 A*；局部地图是真实平面图以底盘为中心、3 m 见方的裁剪（`map.py:_get_local_map_gt`），无传感器半径/遮挡。
4. **碰撞判定用观测局部图**：`check_collision(local_map)`（`combined_env.py:371,184-188`）。若非全局模式改变观测地图，碰撞必须改用真值图，否则会改变终止语义。
5. **布局是规则交错网格**：`SimpleObstacleMap` 间距硬编码 3.0 m（`map.py:837`）。非全局下“猜未见区域”可被网格先验解决，需手写先验对照。

结论：之前的路线在回合开始就用全图规划好，底盘只需沿无碰撞参考走，SAC 主要在调 IK 可达性；控制误差与前瞻难以改变结果，这与 Stage0/FOLLOWUP/SCREEN/CEIL 的负结果一致。
