## 判断与建议（不是新增研究决策）

- 值得检验：移动操作中的基座动作同时影响避障和机械臂可达性，动作条件前瞻有潜在用途；不保证收益。
- 关键风险：低特征 MSE 不等于降低任务失败；潜在差异不是实际预测误差，错误预测也会误导修正；确定性 analytical 环境可能让当前策略已掌握大部分信息，收益可能只出现在部分可观测/扰动条件。
- 研究贡献需要结构匹配对照与失败模式证据；“已有方法换机器人”本身不保证足够创新。若出现可解释、稳定、跨任务的闭环收益，研究说服力更强。
- 硬件路线：本地做 P0 正确性、P1a 和 P2 小规模功能验证；P0 稳定后即准备服务器镜像与相同 batch/rollout 兼容测试，在正式多种子基线/消融前迁移批量训练。服务器若已免费可用，可更早部署；若需租用，先完成最小闭环初筛再扩大投入。
- P1b/P2-SEQ/P3 更值得服务器训练；P4 训练可在服务器，控制耗时必须在目标部署硬件重新测试。P5 根据实际编码器和图像 batch 测量，不预设必须超大 GPU。
- 迁移触发建议：实际显存长期超过约 85% 或限制必要序列/batch；一次候选方案的训练加评估超过一天；多种子/多变体开始排队影响迭代。它们是项目管理阈值，不是物理硬件定律。
- 以 24 GB 以上 GPU 作为序列实验规划起点，不作为已验证最低要求或购买清单；CPU 单核速度、并发可用核数、主存和本地 SSD 同样重要。
- 未实测修复后的吞吐；不根据旧 actor 未更新时的 16.3 step/s 承诺服务器加速倍率或训练工期。
- 多 GPU 首先并行不同 seed/变体，不把现有单进程代码当作自动分布式。迁移时保留 checkpoint/数据/代码哈希，新硬件不承诺逐 bit 一致。
- 旧 PyTorch/CUDA 镜像在新 GPU 上必须实测前向、反向、checkpoint 与 rollout；兼容性不能由显存大小或 nvidia-smi 正常推出。
