## 修正：只计实验耗时的关键路径（2026-09-28T11:25+08:00）

用户指出“时间太紧”应只计实验时间（编码/写作由Agent完成）。此前按常规人工工期判断，撤回“ICML 2027时间过紧”的结论。以下按实测吞吐重估，**均为估算，未做并发实测**。

实测依据：
- SAC analytical：`results/p1a-20260923/sac-screen-100k/summary.json` 100k步/99001更新共11883s（3.3h，≈8.4步/s），其中每次验证+写含replay的checkpoint阻塞12–18min（p1a日志第21、33行）；改为只存策略可省其中大部分。500k约10–16h/run。
- replay_capacity=100000，checkpoint中replay≈11.7GB → 每个训练进程常驻约12–15GB；本机251GB RAM、64核、4×96GB GPU → 估计可并发约12个SAC训练（受RAM限制，未实测并发下单run吞吐）。
- 采数/评测：dataset-v2-10k 9900回合、48进程、4337.8s → 约137回合/min。
- WM训练：P1-RETRAIN-028 实测1000回合约5s/epoch；9600回合外推约50s/epoch，200epoch上限约3h。
- Gazebo：p50 52.8ms/步，只评测不训练，计算量小；但任务SR0、实时预算未达是**工程阻塞**，不是算力问题。

单次通过（不含失败迭代）的纯计算估算：P2快速筛查（4变体×3seed×100k）约半天；路径C失配数据+WM+筛查约1天；正式矩阵（5变体×5seed×500k）约2天；鲁棒性/泛化约1–2天。Husky analytical 核心合计约4–6天。冲A路线再加多机器人（PR2/TIAGo/HSR，未验证可运行）和标准动力学失配基准，约再加1–1.5周。

修正后的判断：纯算力不构成 ICML 2027（A，约1月下旬，未核实）/ IJCAI 2027（B）的障碍。真正的约束是：(1) 假设能否成立，由P2筛查与路径C对照决定，每失败一次多一个约1–2天的迭代周期；(2) ICRA/T-RO 路线需要Gazebo物理验证乃至实机，这是工程/人力阻塞；(3) ML 会议主要看跨基准的方法泛化，对 Gazebo/实机依赖较小，因此在当前 Gazebo 未通过的情况下，冲A路线未必比B路线慢。
