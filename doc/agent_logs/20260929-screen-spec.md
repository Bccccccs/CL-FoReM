- 形式：与 FOLLOWUP-028 相同，执行 Agent 写代码、验证、一次性启动无人值守流水线后结束，流水线跑完后自动生成报告。

## 1. 为什么做这次筛选

Stage0 与 FOLLOWUP-028 的结果（[stage0 日志](20260928-stage0.md)、[FOLLOWUP 日志](20260928-followup-pipeline.md)）说明，在当前 simpleobstacle 设定下，前瞻和在线适应都没有用武之地：

- 执行失配（底盘增益、延迟）会被 SAC 的逐步反馈和机械臂 IK 吸收；六类在线适应都挽回不了失配误差。
- IK 失败的开始用当前 IK 偏差就能近乎完全预测（几何预检 AUROC 0.979，世界模型前瞻 0.976），且成败对轻微扰动接近随机。

教训：**先确认“知道未来/当前真实信息能救回多少”，再做方法。** 本次对两个候选场景各做两件事，不写任何世界模型方法代码（L3 探索臂除外）：

1. **伤害测试**：该场景会不会让 SAC 明显变差？
2. **上限测试（开卷）**：给 SAC 真实的当前或未来信息，能恢复多少？并且这部分收益能否被“历史信息”替代？只有“开卷明显好于历史”的场景，世界模型前瞻才有明确空间。

| 线 | 场景 | 反馈为什么救不了 | 开卷信息 | 历史对照 |
|---|---|---|---|---|
| L 线 | 感知延迟：SAC 看到的观测晚 k 步 | 反馈本身是过时的 | 不延迟的当前观测 | 延迟观测 + 最近 k 步已执行动作 |
| D 线 | 动态障碍：障碍在移动 | 单帧看不出障碍往哪走 | 障碍未来 2 s 的位置（D56 修订，原 0.5 s） | 障碍过去 2 s 的位置（D56 修订） |

## 3. L 线：感知延迟

### 开关 `latency-v1`（`p0_runner.py` 与训练入口，默认关闭）

- `--obs-latency-steps k`（默认 0）：SAC 在第 t 步收到的是第 t−k 步的**完整观测**（robot_state 与 local_map）。回合开始 t < k 时使用初始观测。
- `--map-latency-steps k`（默认 0）：只延迟 local_map，robot_state 保持当前值（对应“关节编码器快、代价地图慢”）。
- 延迟只作用于**策略输入**；环境内部的奖励、终止、碰撞、IK 计算仍使用真实当前状态。
- `--obs-action-history k`（默认 0）：在 robot_state 末尾追加最近 k 个已执行动作（3k 维），不足时补 0。用于“历史对照”策略，开启后观测维度变化，需在 checkpoint 中记录。

### L1 伤害测试（不训练，约 15 min）

policy-100k，确定性，种子 10000–10099，7 个配置：名义；全延迟 k ∈ {1, 2, 3, 5}；仅地图延迟 k ∈ {2, 5}。同种子配对。

报告：成功率、perfect-success、碰撞回合比例、IK 失败回合比例、失败原因分布。

**判据（D53-L1）**：某配置成功率相对名义下降 ≥ 0.15 且配对 CI 上界 < 0。
- 若在 k ≤ 3（≤ 0.3 s）的配置上达到 → **现实档通过**；
- 若只在 k = 5 达到 → **压力档通过**；
- 都没有 → L 线伤害不通过，L2 不运行（L3 仍运行，作为信息）。

### L2 上限测试（训练，约 3.5 h，仅在 L1 通过时运行）

- 选定延迟 k_sel（预登记规则）：取全延迟配置中**最小**的通过 k；若全延迟都不通过而仅地图延迟通过，取仅地图延迟中最小的通过 k，并按仅地图延迟训练。
- 训练 3 种 SAC × 2 个种子 = 6 个：

| 臂 | 训练与评测时的输入 | 含义 |
|---|---|---|
| L-oracle | 不延迟（k = 0） | 开卷上限 |
| L-stale | 延迟 k_sel | 学会在延迟下工作的普通 SAC |
| L-hist | 延迟 k_sel + 最近 k_sel 个动作 | 历史对照（对应 Stage1 的 S2） |

- 每个 checkpoint 在其训练时的输入条件下评测 100 回合（种子 10000–10099）。

**判据（D53-L2）**：两个训练种子的回合合并配对（同评测种子、同训练种子配对），两项都满足才通过：
1. SR(L-oracle) − SR(L-hist) ≥ 0.10，且按“训练种子 × 回合”分层 bootstrap 的 95% CI 下界 > 0；
2. SR(L-oracle) − SR(L-stale) 的 CI 下界 > 0。

含义：延迟造成的损失，训练和历史都补不回来，才说明需要“把旧观测推演到当前”的前瞻。

### L3 探索性：世界模型补偿（不训练，不作通过依据）

在 k_sel（若 L1 不通过，则用 k = 3）上，用 policy-100k：
- 臂 `stale`：SAC 直接看延迟观测（即 L1 该配置）。
- 臂 `wm-comp`：先把延迟观测编码为特征，再用世界模型和**已执行的**动作 a_{t−k} … a_{t−1} 推演 k 步，得到估计的当前特征，送入 SAC 动作头（逆标准化后经 `post_fc_stack → mean_linear → tanh`）。仅地图延迟时，只用推演结果替换 map 块，robot 块用真实当前值。
- 报告：成功率与 SR 恢复比例 = (SR_wm − SR_stale) / (SR_nominal − SR_stale)，配对 CI。
- 动作头实现必须有测试证明与 `policy.predict(..., eval=True)` 一致（FOLLOWUP-028 的 `foresight.py` 已有实现和测试，可复用）。

## 4. D 线：动态障碍

### 开关 `dynmap-v1`（默认关闭）

- 使用现有 `dynObstacle` 任务（`modulation/envs/tasks.py` 中的 `DynamicObstacleTask`：16 个障碍、速度 0.10–0.15 m/s、到达目标后重新采样）。先确认它能在 analytical 下经 `p0_runner.py` 训练和评测；p0_runner 的任务参数若不支持，只做最小改动。
- `--dyn-freeze`（仅评测用，默认关闭）：障碍保持初始位置不动，用于伤害测试。
- `--dyn-map-mode {current,future,past}`（默认 current）：局部地图中障碍的画法，**只改策略输入，碰撞与奖励仍用真实当前位置**。
  - `future`：在当前位置之外，再叠加障碍 **20 步（2.0 s）**后的位置（D56 修订，原为 5 步），取两者的并集（单通道，形状不变）。未来位置通过复制障碍对象及其随机数状态向前模拟 20 步得到（期间可能重新采样目标），不得影响真实障碍的随机数序列。
  - `past`：在当前位置之外，再叠加障碍 **20 步前**的位置（并集，D56 修订），用于历史对照。与 `future` 信息量对称、形状相同。

### D0 可行性（前置）

`dynObstacle` 能完成 reset、step、评测；记录一个 2000 步的训练冒烟。若任务无法运行，D 线终止并在报告中说明原因。

### D1 训练（约 3.5 h，与 L2 并行）

3 种 SAC × 2 个种子 = 6 个，全部在 `dynObstacle` 上训练 100k 步：

| 臂 | 地图模式（训练与评测一致） | 含义 |
|---|---|---|
| D-std | current | 普通 SAC |
| D-oracle | future | 开卷上限 |
| D-hist | past | 历史对照 |

### D2 评测

- 每个 checkpoint 在自己的地图模式下，种子 10000–10099 评测 100 回合。
- 伤害测试：D-std 在障碍冻结（`--dyn-freeze`）下再评测 100 回合。

**判据（D54）**：
- **D54-harm**：SR(D-std, 冻结) − SR(D-std, 移动) ≥ 0.15 且 CI 下界 > 0（两个训练种子合并，分层 bootstrap）。
- **D54-headroom**：SR(D-oracle) − SR(D-hist) ≥ 0.10 且 CI 下界 > 0；同时 SR(D-oracle) − SR(D-std) 的 CI 下界 > 0。
- 两者都满足才算 D 线通过。另报碰撞回合比例（动态障碍的主要失败方式应为碰撞），用于检查机制。
- 若 D-std 在移动障碍下成功率 < 0.2，说明任务整体太难，结论应谨慎，报告中标注。

## 5. 决策规则（预登记，D52）

| 结果 | 下一步 |

| 只有 L 线通过 | 主线改为“学习型世界模型做感知延迟补偿”，L3 结果作为方法原型的第一份证据 |

| 两者都通过 | 取“开卷 − 历史”差距更大者为主线，另一条作为补充实验 |

## 6. 流水线结构与启动前验证

沿用 FOLLOWUP-028 的编排方式（可以复用其代码与经验）：

- 入口：宿主启动脚本 `doc/agent_logs/20260929-screen-launch.sh` → 容器 `mmhusky-node01` 内 `nohup` 运行编排脚本 `src/modulation_rl/scripts/screen_pipeline.py`；输出根目录 `results/screen-028/`；状态文件 `results/screen-028/status.json`；自动报告 `doc/agent_logs/20260929-screen-report.md`。
- 阶段：

| 阶段 | 内容 | 依赖 |
|---|---|---|
| S0 | 预检（GPU、内存、磁盘、analytical 仿真、checkpoint SHA、git HEAD 与工作区状态） | — |
| S1 | L1 伤害测试 | S0 |
| S2 | D0 可行性 | S0 |
| S3 | D1 训练 6 个 | S2 |
| S4 | L2 训练 6 个 | S1 通过（未通过则标记 skipped） |
| S5 | L3 探索臂 | S1 |
| S6 | D2 评测 | S3 |
| S7 | L2 评测 | S4 |
| S8 | 汇总报告 | 全部（失败或跳过如实标注） |

- S3 与 S4 可并行，共 12 个训练进程；训练时 GPU 分配到 4 张卡上。
- **超时**：训练每个 6 h；评测每臂 1.5 h；离线统计 1 h。FOLLOWUP-028 的 S4 因 bootstrap 超时，本次统计必须向量化或减少重复计算，且**先写出点估计结果文件，再计算 CI**，这样超时也不丢结果。
- 每阶段写 `DONE`/`FAILED` 与 `result.json`，可续跑；失败阶段不影响不依赖它的阶段。训练支持从最近 checkpoint 续训（若 p0_runner 的 `--resume` 适用）。
- 停止方式、续跑方式写进启动脚本注释与任务日志。

**启动前必须完成**（写进任务日志）：

1. **默认关闭回归**：种子 10000–10019，不带新开关的评测与改动前代码逐字段一致（episodes.jsonl、轨迹文件）；新开关设为默认值时也一致。
2. **单元测试**：延迟缓冲（回合开头、k = 0 恒等）；动作历史拼接；`future`/`past` 地图不改变真实障碍的随机数序列与位置（关键）；冻结障碍；世界模型补偿的动作头一致性；统计函数。现有测试全部通过。
3. **小规模冒烟**：每类训练 2000 步、每个评测臂 4 回合，全流程跑通并生成报告，输出到 `results/screen-028-smoke/`。
4. 按路径提交到 `screen-028` 分支后再启动正式流水线；确认训练与评测进程已运行后，写好监控与停止方式，结束会话。
